# Подключение журнала преподавателя

Сайт уже содержит URL и публичный Publishable key вашего проекта `gqcpggufehylcwlnduzi`. Ключ можно публиковать на GitHub: чтение журнала ограничено правами базы. Пароли, Secret key и `service_role` в файлы сайта добавлять нельзя.

Для активации журнала выполните следующие шаги в своём аккаунте Supabase. Они ещё не выполнены автоматически.

## 1. Создайте таблицы и правила доступа

1. Откройте SQL Editor: https://supabase.com/dashboard/project/gqcpggufehylcwlnduzi/sql/new
2. Скопируйте **всё содержимое** `supabase-setup.sql` в новый запрос и нажмите **Run**.
3. Убедитесь, что запрос завершился без ошибок. Он создаёт таблицы `attempts`, `teachers` и функцию `submit_attempt`; результаты при повторном запуске не удаляются.

## 2. Создайте учётную запись преподавателя

1. Откройте **Authentication → Users** в этом проекте.
2. Выберите **Add user → Create new user**. Введите вашу почту и придумайте пароль. Включите подтверждение почты (**Auto Confirm User**), если оно предложено.
3. Скопируйте **User UID** созданного пользователя.

Если пользователь с вашей почтой уже существует, используйте его UID и известный вам пароль. Обычная регистрация сама по себе не даёт доступа к журналу.

## 3. Выдайте права преподавателя

В SQL Editor выполните отдельный запрос, подставив User UID из шага 2 вместо `ВСТАВЬТЕ-USER-UID`:

```sql
insert into public.teachers (user_id)
values ('ВСТАВЬТЕ-USER-UID'::uuid)
on conflict do nothing;
```

Для второго преподавателя повторите шаги 2–3. Все добавленные преподаватели видят общий журнал этого проекта. Для отзыва прав удалите соответствующую строку из `teachers` через панель Supabase.

## 4. Обновите сайт на GitHub Pages

Загрузите в тот же репозиторий все файлы из папки `html-css-test` с заменой существующих. Дождитесь публикации. Настройки Pages оставьте прежними: ветка `main`, папка `/ (root)`.

Для учеников адрес прежний. Для преподавателя добавьте к адресу сайта **`teacher.html`**, например `https://ВАШ-ЛОГИН.github.io/html-css-test/teacher.html`. Ссылка также есть внизу главной страницы теста. Вход — почта и пароль из шага 2.

Журнал работает по HTTPS на GitHub Pages. Для локальной проверки используйте HTTP-сервер, а не `file://`.

## 5. Проверьте подключение

1. Пройдите тест под именем «Проверка подключения» и завершите попытку.
2. Дождитесь надписи **«Результат сохранён в журнале преподавателя»**. Если увидите ошибку, проверьте шаг 1 и нажмите **«Повторить отправку»**. Одинаковая попытка повторно не добавляется.
3. В другом браузере или вкладке откройте `teacher.html`, войдите и нажмите **«Обновить»**. Убедитесь, что запись появилась, а её ответы доступны.
4. Проверьте поиск, период и скачивание CSV.
5. После выхода из учётной записи журнал должен показывать форму входа. Неавторизованный участник не должен видеть таблицу результатов.

## Что хранится и кому доступно

В Supabase отправляются имя, выбранные ответы, порядок вопросов, время начала и завершения, случайный ID попытки. База сама вычисляет баллы и добавляет серверную дату получения. Подсказка об отправке есть перед началом теста.

Участник может только отправить результат через ограниченную функцию. Публичный ключ не даёт читать журнал, добавлять преподавателей, менять или удалять результаты. Преподаватель после входа может читать все результаты; интерфейс не удаляет записи.

Вход преподавателя хранится в `sessionStorage` вкладки до истечения токена. После закрытия вкладки или истечения сессии нужно войти заново. Пароль нигде в файлах сайта не сохраняется.

Если интернет пропал, попытка остаётся в браузере, пока не начато новое прохождение. На экране результата есть повторная отправка; при восстановлении интернета страница также попробует отправить результат. Без сообщения об успешном сохранении отправка не считается подтверждённой.

Сайт остаётся учебным тестом: имя вводит сам ученик, правильные ответы доступны в исходном коде, время начала и завершения приходит с устройства. Подсчёт баллов в базе не доказывает личность ученика. Публичная форма приёма не имеет защиты от массовых искусственных отправок. Для закрытого экзамена понадобятся учётные записи учеников и ограничение запросов на сервере.

CSV выгружает до 20 000 попыток, учитывая выбранные имя и период; для большого журнала сужайте период. Даты в интерфейсе и CSV показываются в часовом поясе браузера преподавателя. Фильтр дат применяется к времени получения сервером.

Если меняете вопросы или правильные ответы, обновляйте также SQL-функцию. Для другого теста используйте отдельную версию/таблицу: старые записи разбираются по текущему набору вопросов.

Документация: [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Database functions](https://supabase.com/docs/guides/database/functions), [Supabase Auth](https://supabase.com/docs/reference/javascript/auth-signinwithpassword).
