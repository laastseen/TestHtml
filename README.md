# HTML и CSS — тест из 28 вопросов

Готовый статический сайт для GitHub Pages. Не требует сборки или npm. Для общего журнала используется ваш проект Supabase; настройка описана в `SUPABASE.md`. Все вопросы и правильные ответы перенесены из исходного файла; отметки (+) скрыты в интерфейсе.

## Как опубликовать на GitHub Pages

1. Распакуйте архив. Создайте на GitHub новый публичный репозиторий, например `html-css-test`.
2. Через **Add file → Upload files** загрузите **содержимое** папки `html-css-test`: все HTML, CSS и JS файлы (включая `config.js`, `backend.js`, `sync.js` и файлы `teacher.*`), `.nojekyll` и инструкции. SQL-файл выполняется отдельно в Supabase. Файл `index.html` должен находиться в корне репозитория.
3. Откройте **Settings → Pages**. В разделе **Build and deployment** выберите **Deploy from a branch**.
4. Выберите ветку **main**, папку **/ (root)** и нажмите **Save**.
5. Дождитесь успешной публикации. Адрес сайта появится на странице Pages: `https://ВАШ-ЛОГИН.github.io/html-css-test/`. Разошлите эту ссылку участникам.

Если пункты интерфейса GitHub изменятся, ориентируйтесь на официальную инструкцию: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## Что умеет сайт

- 28 вопросов, по одному правильному ответу из четырёх.
- Обязательное имя участника; перемешивание вопросов можно отключить перед началом.
- Свободный переход между вопросами и изменение ответов до завершения.
- Автоматическое сохранение попытки и итогов в localStorage браузера.
- Восстановление после обновления страницы. Очистка данных браузера удалит прогресс.
- Время без ограничения: учитывает перерывы и закрытую вкладку.
- Подтверждение завершения и предупреждение о пропущенных вопросах.
- Баллы, процент, разбор ответов, скачивание результата в TXT и повторная попытка.
- Адаптивная вёрстка для телефона и компьютера, управление с клавиатуры.
- Автоматическая отправка результата в Supabase с подтверждением и повтором при ошибке.
- Журнал преподавателя (`teacher.html`): вход, поиск, фильтр дат, просмотр ответов, CSV.
- Внешние библиотеки, шрифты и аналитика не используются; данные передаются в ваш Supabase.

## Одновременное прохождение

Посетители получают статические файлы через GitHub Pages, а каждый тест выполняется в браузере участника. Попытки разных пользователей не мешают друг другу. Для общего журнала участники обращаются в Supabase; действуют обычные лимиты GitHub Pages.

На одном устройстве используйте отдельные профили браузера для разных участников. Вкладки одного профиля разделяют хранилище: не проходите разные попытки одновременно в нескольких вкладках. Для нового участника нажмите «Пройти ещё раз» после завершения и сохранения предыдущего результата.

## Результаты и ограничения

После завершения имя, ответы и время передаются в Supabase, где вычисляются баллы. Журнал доступен преподавателю после входа по почте и паролю. Для активации выполните шаги из `SUPABASE.md`: SQL и учётная запись ещё не созданы автоматически. Пока нет подтверждения успешной отправки, результат есть только в браузере; повторите отправку. TXT также можно скачать вручную.

Правильные ответы доступны в исходном JavaScript. Это учебный самотест, а не защищённая экзаменационная система; скачанный отчёт можно изменить. Журнал обеспечивает централизованный сбор, но имя вводит сам участник. Подробности доступа и ограничения описаны в `SUPABASE.md`.

## Изменение вопросов

Откройте `questions.js`: `text` — вопрос, `options` — четыре варианта, `correct` — индекс верного варианта от 0 до 3. Текущий интерфейс рассчитан на 28 вопросов. Также обновите ключ правильных ответов в SQL-функции, не смешивая разные тесты в одном журнале. После изменения содержания поменяйте ключ `KEY` в `app.js`, чтобы старые попытки не использовали изменённые вопросы.

Для проверки используйте локальный HTTP-сервер или опубликованный HTTPS-сайт GitHub Pages. При открытии через `file://` браузер может ограничить сетевые запросы и хранилище.
